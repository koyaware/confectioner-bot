# STATUS2 — полный журнал работ

Дата: 2026-10-03. Язык: русский. Здесь собрано всё, что сделано по проекту,
включая проход QA-аудита по всем стадиям.

## Как устроен проект

- Multi-tenant Telegram-бот для кондитеров: один процесс, один код, много магазинов.
- Каждый магазин — строка в таблице `tenants`, всё остальное привязано через `tenantId`.
- Стек: Node.js 22, TypeScript strict, grammY (long polling), SQLite + Drizzle, zod, vitest.
- Источник истины: `tech.md` (сейчас v1.21). Правила: `CLAUDE.md`.
- QA-артефакты: `docs/qa/test-cases.md`, `docs/qa/bugs.xlsx` (таблицу не удалять).

## Что готово по стадиям

### Стадия 0. Скелет
- Конфиг с zod, SQLite WAL, миграции, `TelegramPort` + `FakePort` с инъекцией ошибок.
- Runner нескольких ботов, middleware: tenant, role, session, antispam, funnel, errors.
- Планировщик джобов с ретраями, `tenant-create`, демо-сид.
- Доработано аудитом: строгий codec callback, валидация payload джобов, 3 ретрая,
  атомарный claim-код, строгая сессия без двойного JSON-кодирования.

### Стадия 1. Каталог и привязка
- Привязка владельца по одноразовому claim-коду (атомарно, с показом owner-меню).
- Редактор категорий/товаров/опций/фото, FAQ, настройки.
- Доработано: tenant-проверка опций, re-prompt фото, лимиты текстов, строгий парсинг admin-ID.

### Стадия 2. Корзина, оформление, загрузка
- Корзина, календарь доступности, шаги оформления, `createOrder` в транзакции.
- Доработано: вся валидация внутри транзакции, адрес обязателен для доставки,
  строгий выбор опций (`BAD_OPTIONS`), `BAD_ADDRESS`, `CUSTOMER_BLOCKED`.

### Стадия 3. Оплата и статусы
- Предоплата, чек, подтверждение/отклонение, напоминания, истечение, pickup-reminder.
- «Мои заказы», отмена клиентом, встречная дата.
- Доработано: атомарный `acceptProposedDate`, проверка даты в `adm:ord:pd`,
  ретраи джобов при повторной оплате, чек после transition, retry коллизии номеров.

### Стадия 4. Диалог и защита
- Relay клиент↔владелец (текст/фото/документ/голос), перегруз, антиспам, блокировка, `BLOCKED`.
- Доработано: команды не перехватываются relay, пауза магазина с гейтом,
  единый `sendCustomerMessage` с уведомлением владельца, текст relay одним сообщением.

### Стадия 5. Продвижение
- Метки источников + QR + шаблоны, статистика 7/30, ежедневная сводка.
- Доработано: backfill источника, безопасные коды, кнопки в карточке ссылки,
  корректные окна статистики, заказы с кнопками в дайджесте.

### Стадия 6. Надёжность
- Бэкап с отправкой суперадмину + `docs/restore.md`, load-sim с гонкой слота,
  `/deleteme`, команды суперадмина, уведомления об ошибках, удаление tenant, docs.
- Доработано: fallback-порт, ротация бэкапов (7 шт.), проверка целостности,
  подтверждение слаугом, расширенное обезличивание.

### Стадия 7. Кастомизация
- Сделана полностью: таблица `feature_flags` + миграция, сервис с `isFeatureEnabled(tenantId, name, default)`, owner-UI в настройках (список, toggle, добавление), codec `adm:set:feat`/`featadd` + контракт v1.22.
- Первая боевая фича: `daily_digest` — владелец может выключить сводку для своего магазина, остальные не affected.
- Проверки: 43 файла / 206 тестов, lint, tsc, prettier, build — зелёные.

### Стадия 8.14–8.23 (критический batch, закрыт)
- Референсы удаляются при переходе на другой экран (трекинг id + cleanup-middleware).
- Загрузка даты: отменённые слот не занимают; подпись «занято X из Y (заказов: N)».
- `prd:add` сливает дубли в одну строку.
- Фотоальбомы считаются поштучно, лимит 5 с удалением лишнего; сообщения юзера удаляются.
- Оформление — строго один экран (`screenMessageId`), ответы юзера удаляются.
- После заказа — возврат в меню + «Заказать ещё»; dead-end экраны с меню-кнопками.
- Relay только через `relay.compose`; чужой текст удаляется с подсказкой; в FAQ кнопка «Задать вопрос».
- Отмена с причиной (`plans`/`date`/`price`/`other`) + «Пропустить», причина в `cancelReason`.
- Календарь: день показывает заказы с кнопками; лимит сохраняется с показом экрана.
- Проверки: 43 файла / 210 тестов, lint, tsc, prettier, build, load-sim — зелёные.
- Toast при добавлении в корзину, кнопка «Перейти в корзину».
- Количество в корзине открывает карточку с опциями; `−`/`+` в карточке.
- Локальные номера заказов у клиента, глобальные у владельца.
- Кнопки ответа владелец↔клиент, подтверждения отправки.
- Красивая сетка «Другой даты» с листанием.
- Валидация чеков, файлы владельцу как файлы, русские подписи.
- Кнопка «Отмена» на экране даты; отмена редактирует сообщение.
- Примеры телефонов по валюте (`₽`, `₸`, `UZS`).
- Скрытые отменённые заказы; референсы видны обеим сторонам.
- Scheduler 30s, load-sim с гонкой.

## Известные ограничения (честно)

- Параллельность — только в одном процессе (SQLite sync); мульти-процесс не тестировался.
- Проверка чеков на вирусы не интегрирована (нет бесплатного API).
- Референсы отправляются отдельными сообщениями (у порта нет альбомов).
- `cart:noop` — техническая инертная кнопка для заголовков сеток.
- Глобальные `backup.db`-джобы не удаляются вместе с tenant (бэкап общий).
