# Стадия 6: Надёжность и пилот — статус

## Что сделано

- **6.1 Бэкап и восстановление** (`7fccc7f`, `c562f3d`)
  - Ежедневно в 03:00 UTC создаётся джоб `backup.db`.
  - Файл БД отправляется в Telegram суперадмину как документ.
  - В проекте есть `docs/restore.md` с инструкцией восстановления и проверкой целостности.
  - Проверено тестами: файл бэкапа открывается и проходит `PRAGMA integrity_check`.

- **6.2 Симуляция наплыва** (`05469b6`)
  - Добавлен `scripts/load-sim.ts` (`npm run load:sim`).
  - Эмулирует 300 клиентов, которые проходят каталог и оформление заказа.
  - Результат прогона:
    - 300 заказов,
    - все order ids и idempotency keys уникальные,
    - загрузка дат не превышена,
    - p95 обработки апдейта: 1 мс (в фейковой среде).

- **6.3 Персональные данные и суперадмин-команды** (`63a5f45`, `48c9386`, `87b681c`)
  - `/deleteme` обезличивает клиента: имя, телефон, адрес, комментарий заменяются на заглушку.
  - Команды суперадмина: `/status`, `/tenants`, `/pause <slug>`, `/resume <slug>`.
  - Необработанные ошибки, падение запуска бота и падение джобов отправляются суперадмину через действующий бот.
  - Важное исправление: команды типа `/deleteme` больше не перехватываются relay и корректно доходят до своих обработчиков.

- **6.4 Документация для владельца** (`3426dd6`)
  - Добавлен `docs/owner-setup.md`.
  - Демо-бот: `npm run seed` создаёт демо-магазин, `npm run dev` запускает бота.
