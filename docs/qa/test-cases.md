# QA test cases: Telegram-бот кондитера

## Статика / загрузка

1. Открыть бота, нажать Start.
2. `/menu` для клиента.
3. `/menu` для владельца.
4. `/menu` для superadmin, который не является владельцем.
5. `/deleteme`.
6. `/status`, `/tenants`, `/pause <slug>`, `/resume <slug>` от superadmin.
7. Команды от обычного клиента в боте другого магазина.
8. Перезапуск процесса: сессии/order callbacks не теряют состояние.

## Главное меню клиента

1. Нажать «Каталог».
2. Нажать «Корзина».
3. Нажать «FAQ».
4. Нажать «Мои заказы».
5. Кнопки групп товаров работают.
6. Выбор опций на товаре.

## Каталог и товар

1. Категории отображаются все.
2. Неактивные категории/товары скрыты.
3. Показывается фото и цена.
4. `leadDays` товара и `minQty`/`maxQty` учитываются.
5. Добавить товар в корзину.
6. Удалить товар из корзины.
7. Карточка товара с фото: фото видно, тогглы опций не плодят сообщения.

## Корзина и checkout

1. Пустая корзина.
2. Открыть корзину.
3. Уменьшить/увеличить количество.
4. Очистить корзину.
5. Начать оформление.
6. Выбор даты.
7. Недоступные даты: занято, дата слишком близкая, закрытая дата.
8. Способ получения.
9. Адрес при доставке.
10. Контакт.
11. Комментарий.
12. Прикрепление фото.
13. Подтверждение.
14. Повторный submit на `chk:submit` не создаёт второй заказ.
15. Отмена checkout.
16. Кнопка «Назад» возвращает на прежний шаг.

## Платежи

1. Владелец принимает заказ в awaiting_payment.
2. Клиент нажимает «Я оплатил».
3. Клиент присылает чек.
4. Владелец подтверждает оплату.
5. Владелец отклоняет оплату.
6. Просрочка оплаты.
7. Установка предоплаты.

## Статусы заказов

1. Новый заказ → принять.
2. Новый заказ → отклонить с причиной.
3. Новый заказ → другая дата.
4. Подтверждённый → готовый.
5. Готовый → завершён.
6. Клиент отменяет new/awaiting_payment.
7. Заказы в «моих заказах» отображаются.

## Owner orders

1. `adm:ord:list` открывает список.
2. `adm:ord:view:<orderId>` открывает карточку.
3. `adm:ord:accept`, `reject`, `ready`, `done`, `cancel` меняют статус.
4. `adm:ord:date` предложить дату (красивая сетка месяца с листанием).
5. `adm:ord:refs:<orderId>` показать референсы.
6. Переписки с клиентом нет; связь только через «📞 Контакты».
7. Повторные нажатия не дублируют переход.

## Owner catalog/FAQ/links/calendar/stats/settings

1. Создать категорию.
2. Переименовать категорию.
3. Включить/выключить категорию.
4. Создать товар.
5. Редактировать цену.
6. Добавить/удалить опцию.
7. Создать FAQ.
8. Редактировать ответ.
9. Удалить FAQ.
10. Создать Instagram source.
11. Открыть source preview с QR.
12. Закрыть день.
13. Изменить лимит.
14. Статистика 7/30.
15. Переключить acceptOrders.
16. Изменить delivery fee.
17. Выбрать язык `Oʻzbekcha`: список настроек уже на узбекском.
18. Выбрать язык `Қазақша`: список настроек уже на казахском.
19. Выбрать валюту `₸`: валюта сменилась, язык текстов не сменился.
20. Невалидные `adm:set:lang:en` / `adm:set:cur:usd` игнорируются.
21. Не-владелец не может сменить язык/валюту.
22. `cnt:show` показывает `contactsText`, без него — fallback.
23. Свободный текст даёт указатель на контакты один раз, повтор молчит 6 ч, владельцу ничего не уходит.

## Привязка владельца

1. `/start` с `claim_` ставит владельца, повтор той же ссылки отклоняется.
2. Просроченный код отклоняется, чужой код отклоняется.
3. Не-владелец не видит owner-разделы в `/menu`.

## Тексты

1. FAQ должен отображаться как `FAQ`.
2. Owner menu должен содержать все разделы.
3. Навигация везде с «Назад».
4. Пустые списки имеют empty-state.

## Матрица язык × валюта

1. `ru` + `₽`, `ru` + `₸`, `uz` + `₽`, `uz` + `UZS`, `kk` + `₸`, `kk` + `₽`: меню и каталог полностью на языке магазина, суммы в валюте.
2. Смена языка не трогает валюту и наоборот.
3. Дата/суммы форматируются локалью языка (`ru-RU`, `uz-Latn`, `kk-KZ`).

## Надежность

1. Два одинаковых `chk:submit` создают один заказ.
2. Повторное открытие экрана заказа не дублирует сообщения (один экран).
3. Ретраи джобов работают.
4. `BLOCKED` от Telegram переводит `botBlocked`.
5. Указатель на контакты не трогает сессию и состояние владельца.

## Безопасность

1. Не-владелец не получает owner-actions.
2. Клиент не видит чужие заказы.
3. Токен не появляется в логах.
4. Адрес/текст клиента не логируются.

## Производительность

1. `npm run load:sim` проходит без duplicates и lost orders.
2. `p95` обработки в симуляции < 200мс.
3. Bot API responds within 1 second for callbacks.
4. DB queries in middleware should not be duplicated unnecessarily.

## Stage 8 регрессия

1. Добавление товара показывает toast, отдельное сообщение не приходит; на карточке есть «Перейти в корзину».
2. Нажатие на количество в корзине открывает карточку товара с его опциями; `−`/`+` в карточке меняют строку.
3. Сообщения клиенту содержат его локальный номер заказа с 1; владелец видит глобальный номер.
4. Чата с мастером нет: в меню кнопка «📞 Контакты», свободного текста владельцу не уходит.
5. «Другая дата» показывает месяц-сетку с листанием; перенос подтверждает номер клиента.
6. Текст/файл вместо чека → повторная просьба «только фото»; фото уходит владельцу как фото с кнопками.
7. Экран даты оформления имеет кнопку «Отмена».
8. Подсказка телефона соответствует валюте магазина (`₽`, `₸`, `UZS`).
9. Отменённые заказы скрыты из «Мои заказы».
10. Референсы видны владельцу (`adm:ord:refs`) и клиенту (`my:refs`).
11. Голосовое вне сценария даёт указатель на контакты (rate-limited), владельцу ничего не уходит.
12. Кнопка контакта (`request_contact`) присылает имя+телефон и двигает оформление дальше.
13. Дайджест содержит заказы с кнопками просмотра.
14. Перегрузка: переключатель реально включает/выключает приём.
15. Пауза магазина блокирует клиентов, но не суперадмина.

## Stage 7: feature flags

Feature flags управляются через сервис/скрипты (нет UI в настройках).

1. Скрипт/код создаёт флаг для tenant, по умолчанию выключен.
2. Нажатие на флаг в коде/скрипте переключает его.
3. Невалидное имя флага отклоняется с подсказкой формата.
4. Выключенный `daily_digest` останавливает сводки только этого магазина.
5. Флаг одного магазина не виден и не влияет на другой магазин.
6. UI для управления флагами в настройках убран (v1.26); управление через код/скрипты.
